# ระบบตรวจสอบผลงานทางวิชาการและคุณสมบัติอาจารย์/กรรมการ

เว็บแอป (Google Apps Script + Google Sheets) สำหรับงานบริการการศึกษา ใช้ร่วมกันได้ 4 บทบาท ได้แก่ ผู้ยื่นเรื่อง เจ้าหน้าที่ ผู้พิจารณา และผู้ดูแลระบบ

> **ค่าเริ่มต้น = โหมดง่าย:** ผู้ใช้เข้าสู่ระบบด้วยบัญชี @mahidol.ac.th → กรอกชื่อ → เลือกช่วงปี → กดค้นหา → เห็นผลทันที (ค้น Scopus, WoS, PubMed, ERIC, TCI/ThaiJO, OpenAlex พร้อมลิงก์ยืนยันทุกรายการ) — ไม่มีเมนูอื่น
> **ใส่ API key หลังบ้าน:** ที่ต้นไฟล์ `Code.gs` ส่วน `API_KEYS_IN_CODE` วางกุญแจ Scopus ระหว่าง `' '` → บันทึก → รันฟังก์ชัน **testScopus** เพื่อตรวจ (ผลอยู่ใน Execution log) — อย่าแชร์ไฟล์หรือส่งกุญแจในแชต
> ระบบคำขอแบบเต็ม (บทบาท/เกณฑ์/ขั้นตอนอนุมัติ ด้านล่าง) ยังอยู่ — เปิดได้โดยแก้ค่า `SIMPLE_MODE` เป็น `false` ในชีต Settings

> **สถานะปัจจุบัน:** ระบบทำงานได้ครบทุกขั้นตอน **แต่ยังไม่ได้เชื่อมต่อ MUHR และ MUREX จริง** — ระบบใช้ข้อมูลจำลอง (สมมติทั้งหมด) หรือไฟล์ CSV ที่ผู้ดูแลนำเข้า
> ชุดเกณฑ์ที่ติดมากับระบบเป็น **"สำหรับสาธิต"** เท่านั้น ห้ามใช้ตัดสินคำขอจริง

## 2. ติดตั้งครั้งแรก

> **สำคัญ:** สร้างไฟล์ Google Sheets และ Apps Script ด้วย **บัญชี @mahidol.ac.th** — ถ้าสร้างด้วย Gmail ส่วนตัว จะเลือก "ทุกคนในมหาวิทยาลัยมหิดล" ตอน Deploy ไม่ได้ และระบบจะไม่รู้อีเมลของผู้ใช้

1. เข้าสู่ระบบ Google ด้วยบัญชี @mahidol.ac.th → สร้าง Google Sheets ใหม่ 1 ไฟล์ → เมนู **ส่วนขยาย → Apps Script**
2. วางไฟล์ทั้ง 3 ตามตารางด้านบน
3. **กำหนดผู้ดูแลระบบคนแรก:** ที่บรรทัดต้นไฟล์ `Code.gs` แก้
   `const FIRST_ADMIN_EMAIL = '';` เป็น `const FIRST_ADMIN_EMAIL = 'ชื่อ.นามสกุล@mahidol.ac.th';` (หลายคนคั่นด้วย `,`)
   — ถ้าเว้นว่าง ระบบจะตั้ง "คนที่กด setup" เป็นผู้ดูแล **เฉพาะเมื่อเป็นบัญชี @mahidol.ac.th** · อีเมลนอกโดเมนจะถูกข้าม
   — กด 💾 บันทึก
4. ที่รายการฟังก์ชันข้างปุ่ม ▶ ต้องเป็น **setup** (ไม่ใช่ api / doGet) → กด **▶ เรียกใช้** → อนุญาตสิทธิ์ (Sheets, Drive, อีเมลของผู้ใช้, เชื่อมต่อบริการภายนอก) แล้วดู "บันทึกการดำเนินการ"
   - สร้างชีตทั้งหมด และตั้งผู้ดูแลตามข้อ 3 (มีทุกบทบาท สลับได้จากเมนูผู้ใช้)
   - สร้างข้อมูลสาธิต + บัญชีทดสอบ 7 บัญชี + คำขอตัวอย่าง 4 รายการ
   - ถ้าขึ้น `*** ยังไม่มีผู้ดูแลระบบ` ให้ใส่อีเมลในข้อ 3 แล้วรัน setup อีกครั้ง (รันซ้ำได้ ไม่สร้างข้อมูลซ้ำ)
5. **ทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป**
   - ดำเนินการในฐานะ: **ฉัน**
   - ผู้มีสิทธิ์เข้าถึง: **ทุกคนในมหาวิทยาลัยมหิดล**
6. ส่งลิงก์ `/exec` ให้ผู้ใช้ได้เลย

**ใครเข้าได้บ้าง:** ทุกคนที่ใช้บัญชี **@mahidol.ac.th** เปิดลิงก์แล้วเข้าใช้ได้ทันที ระบบลงทะเบียนให้อัตโนมัติในบทบาท **ผู้ยื่นเรื่อง** (เห็นเฉพาะคำขอของตัวเอง) — บทบาท **เจ้าหน้าที่ / ผู้พิจารณา / ผู้ดูแล** ผู้ดูแลเป็นคนกำหนดในหน้า "ผู้ใช้และสิทธิ์" (แก้ชื่อที่แสดงได้ที่หน้าเดียวกัน) · บัญชีนอกโดเมน (เช่น Gmail) เข้าไม่ได้ · ถ้าต้องการให้ผู้ดูแลเพิ่มผู้ใช้เองทุกคน ปิด "ให้ทุกคนในโดเมนเข้าใช้ได้ทันที" ในหน้า ตั้งค่า

> **อัปเดตจากเวอร์ชันก่อน:** วางทับ 3 ไฟล์ → รัน **setup** อีกครั้งเพื่ออนุญาตสิทธิ์ใหม่ (เชื่อมต่อบริการภายนอก — ใช้เรียก Scopus/MUREX/MUHR) → Deploy เวอร์ชันใหม่ ข้อมูลเดิมไม่หาย

> แก้โค้ดภายหลัง: ต้อง **ทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้ → ✏️ → เวอร์ชันใหม่** ลิงก์เดิมจึงจะได้โค้ดใหม่

## 3. เริ่มทดลองใช้ (บัญชีทดสอบแต่ละบทบาท)

โหมดทดสอบเปิดอยู่หลังติดตั้ง: คลิกชื่อผู้ใช้มุมขวาบน → **เปลี่ยนบัญชีทดสอบ** → เลือกบัญชี (ต้องเข้าด้วยบัญชี @mahidol.ac.th ก่อน) · กลับเป็นบัญชีตัวเองได้จากเมนูเดียวกัน

| บัญชีทดสอบ | บทบาท | หน่วยงาน | ลองทำอะไร |
|---|---|---|---|
| ผู้ยื่นทดสอบ ก | ผู้ยื่นเรื่อง | คณะตัวอย่าง ก | สร้างคำขอ, แก้คำขอที่ถูกส่งกลับ (RQ…-0002) |
| ผู้ยื่นทดสอบ ข | ผู้ยื่นเรื่อง | คณะตัวอย่าง ข | ดูว่าเห็นเฉพาะคำขอของตัวเอง |
| เจ้าหน้าที่ทดสอบ ก | เจ้าหน้าที่ | คณะตัวอย่าง ก | คิวงาน, ยืนยันตัวบุคคล/ผลงาน, ตัดสินรายการซ้ำ |
| เจ้าหน้าที่ทดสอบ ข | เจ้าหน้าที่ | คณะตัวอย่าง ข | รับเรื่อง RQ…-0003 (ข้อมูลบุคคลเก่า → "ยังสรุปไม่ได้") |
| ผู้พิจารณาทดสอบ ก / ข | ผู้พิจารณา | ก / ข | บันทึกผลพิจารณาพร้อมเหตุผล |
| ผู้ดูแลทดสอบ | ผู้ดูแลระบบ | ทุกหน่วยงาน | ชุดเกณฑ์, นำเข้า CSV, ผู้ใช้, ตั้งค่า, บันทึกการใช้งาน |

บุคคลสมมติใน MUHR จำลอง: `T0001`–`T0006` (มีชื่อซ้ำ "สมชาย ทดสอบดี" 2 คน, ชื่อเดิม "Malee Sommatisakul", ข้อมูลเก่า `T0005`, ข้อมูลไม่ครบ `T0006`, เกษียณ `T0004`)

**ก่อนใช้งานจริง:** ตั้งค่า → ปิดโหมดทดสอบ → "ล้างข้อมูลสาธิต" → เพิ่มผู้ใช้จริงในหน้า ผู้ใช้และสิทธิ์

## 4. ขั้นตอนงาน

สร้างคำขอ → เลือกประเภท → ค้นหาและยืนยันบุคคล → รวบรวมผลงาน → ตรวจตามเกณฑ์ (อัตโนมัติเมื่อยื่น) → เจ้าหน้าที่ตรวจยืนยัน → ผู้มีอำนาจพิจารณา → แจ้งผลและปิดงาน

- บันทึกร่างได้ทุกขั้น · ตรวจความครบถ้วนก่อนยื่น · ขอเฉพาะเอกสารที่จำเป็นตามประเภทและเงื่อนไข
- ส่งกลับแก้ไขเป็นรายการ ผู้ยื่นแก้ได้ **เฉพาะส่วนที่ระบุ** ข้อมูลอื่นคงไว้ · ยื่นใหม่กลับไปหาเจ้าหน้าที่คนเดิม
- ยกเลิกได้พร้อมเหตุผล · เก็บข้อมูลเดิม ไฟล์ที่ถูกนำออก ผลตรวจทุกครั้ง และประวัติสถานะทั้งหมด
- ทุกหน้าคำขอบอก **สถานะ / ใครรับผิดชอบตอนนี้ / ขั้นต่อไป** สถานะแสดงทั้งไอคอนและข้อความ (ไม่ใช้สีอย่างเดียว)

## 5. หลักการตรวจ

- **ยืนยันตัวบุคคล:** ใช้รหัสบุคลากรเป็นหลัก ค้นด้วยชื่อไทย/อังกฤษ/ชื่อเดิมได้ แต่ผลที่เลือกจากชื่อ **ต้องให้เจ้าหน้าที่ยืนยัน** เสมอ ชื่อซ้ำจะแสดงเตือน
- **ผลงานซ้ำ:** ตรวจ DOI ก่อน แล้วจึงดูชื่อเรื่อง+ปี → แสดงเป็น "สงสัยว่าซ้ำ" ให้เจ้าหน้าที่ตัดสิน **ไม่รวมรายการเอง** และไม่ลบ (รายการที่ซ้ำถูก "คัดออก" แต่ยังเก็บไว้)
- **ผลรายเกณฑ์:** ผ่าน / ไม่ผ่าน / ยังสรุปไม่ได้ พร้อมเหตุผล ข้อมูลที่ใช้ และหลักฐาน
- **ค้นไม่พบ ข้อมูลไม่ครบ ข้อมูลเก่า ระบบต้นทางขัดข้อง ยังไม่ยืนยันตัว ผลงานรอตรวจ มีรายการซ้ำค้าง → "ยังสรุปไม่ได้" เสมอ** ระบบจะสรุปว่า "ไม่ผ่าน" ได้เฉพาะเมื่อข้อมูลยืนยันแล้วและครบถ้วน (ข้อผลงาน: ต้องมีเจ้าหน้าที่ยืนยันว่ารายการครบถ้วน)
- ผลตรวจทุกครั้งผูกกับ **เวอร์ชันเกณฑ์ + snapshot ข้อมูล** · ประเมินซ้ำได้ (ต้องระบุเหตุผล) ผลเดิมยังอยู่
- **ผลของระบบแยกจากผลพิจารณา** ผู้พิจารณาต้องระบุเหตุผลทุกครั้ง

| ขั้นตอนคำขอ ร่าง ส่งกลับ ยื่นใหม่ ยกเลิก ประวัติ | ✅ ใช้งานได้ |
| ค้นหาบุคคล ยืนยันตัว ตรวจชื่อซ้ำ ตรวจผลงานซ้ำ | ✅ ใช้งานได้ |
| **ค้นผลงานจาก Scopus → WoS → PubMed → ERIC → TCI/ThaiJO → OpenAlex** (ในขั้น "ผลงาน") | ✅ ใช้งานได้จริง — Scopus ค้นโดยตรงเมื่อใส่ API key |

## 7. วิธีเชื่อม MUREX, MUHR และ Scopus

ทุกอย่างทำในหน้า **แหล่งข้อมูล/นำเข้า** (ผู้ดูแลระบบ) — กุญแจเก็บใน Script Properties ไม่อยู่ในโค้ด และสถานะจะขึ้น "เชื่อมต่อแล้ว" **เฉพาะเมื่อกดทดสอบผ่าน** ด้วยค่าตั้งค่าปัจจุบัน

**Scopus และฐานข้อมูลวิชาการ**

ขั้นที่ 0 — ให้สคริปต์เชื่อมต่อภายนอกได้ (ต้องทำก่อน ไม่งั้นทุกฐานขึ้น "ขัดข้อง")
1. Apps Script → เลือกฟังก์ชัน **testConnection** → Run → อนุญาตสิทธิ์ (มีรายการ "เชื่อมต่อกับบริการภายนอก")
2. Execution log ต้องขึ้น `OpenAlex: เชื่อมต่อได้`, `PubMed: เชื่อมต่อได้` …
3. Deploy → จัดการการทำให้ใช้งานได้ → ✏️ → **เวอร์ชันใหม่** → Deploy
   (PubMed, ERIC, OpenAlex, Crossref, TCI ผ่าน Crossref ใช้ได้ทันทีหลังขั้นนี้ ไม่ต้องมี key)

ขั้นที่ 0.5 — ไม่มี API key ก็ตรวจ Scopus + Quartile ได้ (แนะนำให้ทำทันที)
1. Apps Script → เลือกฟังก์ชัน **importSjr** → Run → Execution log ต้องขึ้น `นำเข้ารายชื่อวารสาร Scopus จาก SJR 2024 แล้ว … ISSN`
2. ระบบจะดึงรายชื่อวารสารทั้งหมดใน Scopus พร้อม Quartile จาก SCImago (scimagojr.com — ฟรี ใช้ข้อมูล Scopus) มาเก็บในชีต JournalIndex
3. ผลงานที่พบจาก OpenAlex / PubMed / Crossref จะถูกจับคู่ ISSN → ขึ้นว่า "Scopus · Q1" พร้อมที่มา "SJR 2024" (ระดับ "วารสารอยู่ในรายชื่อฐาน" — ยืนยันระดับบทความได้เมื่อมี Scopus API key)
4. รันซ้ำปีละครั้งเมื่อ SJR ปีใหม่ออก · ถ้าดาวน์โหลดอัตโนมัติไม่ได้ ระบบจะบอกวิธีดาวน์โหลดเอง

**กรอกแค่ชื่อไทย:** ระบบหาชื่ออังกฤษจาก OpenAlex ให้เอง (จากชื่อสำรองของนักวิจัย หรือผู้แต่งในบทความภาษาไทย) แล้วค้นฐานนานาชาติต่อ — ถ้าพบหลายคนจะให้เลือก · ถ้าไม่พบ ให้ใส่ชื่ออังกฤษใน "ตัวเลือกเพิ่มเติม"

ขั้นที่ 1 — ขอ Scopus API key (ฟรีสำหรับมหาวิทยาลัยที่บอกรับ Scopus)
1. เปิด https://dev.elsevier.com → กด **I want an API Key**
2. Sign in / Register ด้วย **อีเมล @mahidol.ac.th** (บัญชี Elsevier เดียวกับที่ใช้ Scopus/ScienceDirect ได้)
3. กด **Create API Key** → Label: `MU Academic Search` → Website URL: ใส่ลิงก์ `/exec` ของเว็บแอป (หรือ https://mahidol.ac.th) → ติ๊กยอมรับเงื่อนไข → Submit
4. คัดลอก key (ตัวอักษร 32 ตัว)

ขั้นที่ 2 — ใส่ key หลังบ้าน
1. `Code.gs` ต้นไฟล์ → `SCOPUS_API_KEY: 'วางตรงนี้',` → 💾
2. Run **testScopus** → ต้องขึ้น `Scopus: ผ่าน`
3. Deploy เวอร์ชันใหม่

ขั้นที่ 3 — ถ้า testScopus ขึ้น 401 / 403 / AUTHORIZATION_ERROR
Apps Script เรียก API จากเซิร์ฟเวอร์ของ Google (ไม่ใช่เครือข่ายมหาวิทยาลัย) Elsevier จึงไม่รู้ว่าเป็นมหิดล → ต้องมี **Institutional Token**
- ติดต่อ **หอสมุดและคลังความรู้ มหาวิทยาลัยมหิดล** แจ้งว่า "ขอ Scopus API Institutional Token (insttoken) สำหรับ API key ……" (หอสมุดประสานกับ Elsevier)
- ได้แล้ววางที่ `SCOPUS_INSTTOKEN: '…'` → testScopus อีกครั้ง

ขั้นที่ 4 (ไม่บังคับ) — Web of Science
https://developer.clarivate.com → Register → APIs → **Web of Science Starter API** → Subscribe (แผนฟรีสำหรับสถาบันที่บอกรับ) → Applications → คัดลอก key → `WOS_API_KEY: '…'`

ขั้นที่ 5 (แนะนำ) — รายชื่อวารสาร SJR/TCI สำหรับ Quartile และ TCI กลุ่ม 1/2: ปิดโหมดง่ายชั่วคราว (`SIMPLE_MODE` = false ในชีต Settings) → หน้า แหล่งข้อมูล → นำเข้ารายชื่อ → เปิดโหมดง่ายกลับ

**MUREX (Elsevier Pure)** — MUREX ของมหาวิทยาลัย (murex.mahidol.ac.th) ทำงานบนระบบ Pure ของ Elsevier ซึ่งมี Pure API
1. ขอ **Pure API key** จากผู้ดูแลระบบ MUREX (งานบริหารงานวิจัย / ทีม Pure) — กุญแจสร้างในแท็บ Administrator ของ Pure ต้องให้สิทธิ์อ่าน *persons* และ *research-outputs*
2. ขอข้อมูลยืนยัน: URL ของ API (ค่าเริ่มต้น `https://murex.mahidol.ac.th/ws/api`), เวอร์ชัน Pure, และ**ข้อมูลบุคคลใน Pure มีรหัสบุคลากร (Employee ID) หรือไม่** — ระบบใช้รหัสนี้จับคู่คน
3. ในส่วน "เชื่อมต่อ API: MUREX" เลือกชุดตั้งค่า **Elsevier Pure** → วางกุญแจ → แก้ URL/รูปแบบคำขอถ้าผู้ดูแลแจ้งต่างจากค่าเริ่มต้น → บันทึก
4. กรอกรหัสบุคลากรของคนจริง 1 คน → **ทดสอบการเชื่อมต่อ** → ผ่านแล้วเปลี่ยนโหมด MUREX เป็น "เชื่อมต่อ API"

**MUHR** — ไม่พบเอกสาร API สาธารณะ ต้องขอจากกองทรัพยากรบุคคล/กองเทคโนโลยีสารสนเทศ:
URL, วิธียืนยันตัวตน (ชื่อ header + กุญแจ), คำขอค้นบุคคลด้วยชื่อ และด้วยรหัสบุคลากร, ชื่อฟิลด์ในผลลัพธ์ (รหัส ชื่อไทย/อังกฤษ ชื่อเดิม หน่วยงาน ตำแหน่ง ตำแหน่งวิชาการ คุณวุฒิ สถานะ วันที่ปรับปรุง), รหัสค่า (code list), โควตา และผู้ติดต่อเมื่อขัดข้อง
จากนั้นกรอกในส่วน "เชื่อมต่อ API: MUHR" (ชุดตั้งค่า "กำหนดเอง" — จับคู่ฟิลด์ด้วย JSON เช่น `{"staffCode":"emp.code","firstNameTh":"th.first"}`) → ทดสอบ → เปลี่ยนโหมด
ระหว่างรอ ใช้ **นำเข้า CSV** ได้

ข้อกำหนดทางกฎหมาย: ขออนุญาตใช้ข้อมูลส่วนบุคคลตามวัตถุประสงค์ (PDPA) จากเจ้าของข้อมูล/ผู้ควบคุมข้อมูลก่อนเชื่อมจริง · Apps Script เรียก API จากเครื่องของ Google (ไม่ใช่เครือข่ายมหาวิทยาลัย) — ถ้าระบบปลายทางเปิดเฉพาะ IP ภายใน จะต้องขอเปิดทาง

## 8. สิ่งที่หน่วยงานต้องยืนยัน (อยู่ในหน้า ตั้งค่า / ชุดเกณฑ์)

- **ชุดเกณฑ์จริงของแต่ละประเภทคำขอ:** ข้อความเกณฑ์ ค่า (เช่น จำนวนผลงาน ช่วงปี ประเภทผลงานที่นับ คุณวุฒิ ตำแหน่ง) แหล่งอ้างอิง (ประกาศ/ข้อ) วันที่มีผล และผู้ยืนยัน — ระบบไม่ยอมเปิดใช้เกณฑ์จริงถ้าขาดข้อมูลเหล่านี้
- ประเภทคำขอและเอกสารที่ต้องใช้ของแต่ละประเภท
- จำนวนวันที่ถือว่าข้อมูลต้นทาง "เก่า" (ค่าเริ่มต้น 180 วัน)
- ขนาดและชนิดไฟล์ที่ยอมรับ (ค่าเริ่มต้น PDF/PNG/JPG ไม่เกิน 10 MB)
- หน่วยงานและขอบเขตงานของผู้ใช้แต่ละคน
- การแจ้งเตือนภายนอก (ถ้าต้องการอีเมล ต้องเพิ่มสิทธิ์ `script.send_mail` ใน appsscript.json และเขียนส่วนส่งอีเมล — ปัจจุบันปิดและเปิดจากหน้าเว็บไม่ได้)

## 9. ความปลอดภัย

- เข้าได้เฉพาะบัญชี @mahidol.ac.th (แก้โดเมนได้ในหน้า ตั้งค่า) รวมถึงตอนใช้บัญชีทดสอบ · ผู้ที่ลงทะเบียนอัตโนมัติได้เฉพาะบทบาทผู้ยื่นเรื่อง
- ตรวจสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ทุกคำสั่ง ไม่เชื่อบทบาทที่หน้าเว็บส่งมา · ผู้ยื่นเห็นเฉพาะคำขอของตน · เจ้าหน้าที่เห็นเฉพาะหน่วยงานที่รับผิดชอบ · ผู้พิจารณาเห็นเฉพาะคำขอที่ส่งถึงตน
- ไฟล์ตรวจชนิดจากเนื้อไฟล์จริง จำกัดขนาด เก็บในโฟลเดอร์ Drive ที่ไม่แชร์ หน้าเว็บไม่ได้รับรหัสไฟล์ Drive — เปิดไฟล์ได้ผ่านระบบที่ตรวจสิทธิ์เท่านั้น **ห้ามแชร์โฟลเดอร์ "RV — ไฟล์แนบคำขอ"**
- นำเข้า CSV ตรวจคอลัมน์/ค่า/แถวซ้ำ และต้องตรวจทานก่อนบันทึก
- บันทึกการใช้งาน (ชีต Audit): ผู้ทำ การกระทำ เวลา รายการ ชื่อฟิลด์ที่เปลี่ยน เหตุผล — ไม่บันทึกค่าข้อมูลส่วนบุคคล
- ไม่มีรหัสผ่านหรือกุญแจในโค้ด
- ปิดโหมดทดสอบก่อนใช้งานจริง (โหมดทดสอบให้ทุกคนที่เข้าเว็บเลือกใช้บัญชีทดสอบได้)

## 10. การทดสอบ (สำหรับผู้พัฒนา)

```bash
node dev/build-review-bundle.mjs        # สร้าง review/ (3 ไฟล์) และหน้าตัวอย่าง dev/preview-review/
node dev/test-review.mjs                # 25 ชุดทดสอบฝั่งเซิร์ฟเวอร์ (BUNDLE=1 = ทดสอบไฟล์รวม)
node dev/e2e-review.mjs                 # ทดสอบหน้าเว็บ: ตรวจ → ส่งต่อ → ตัดสิน → ปิดงาน
node dev/screenshots-review.mjs         # ภาพหน้าจอ docs/review-images/
```

ชุดทดสอบครอบคลุม: ค้น Scopus/ฐานข้อมูลและเพิ่มผลงานพร้อมลิงก์ยืนยัน, เกณฑ์ฐานข้อมูล/Quartile, MUREX ผ่าน Pure API (กุญแจผิด/ระบบล่ม/ต้องทดสอบใหม่เมื่อแก้ค่า), MUHR ผ่าน API, เข้าได้เฉพาะ @mahidol.ac.th และลงทะเบียนอัตโนมัติเป็นผู้ยื่นเรื่อง, ผู้ดูแลคนแรก, สิทธิ์ตามบทบาท (รวมการปลอมบทบาท), ชื่อซ้ำ, ผลงานซ้ำ, ข้อมูลไม่ครบ, ระบบต้นทางขัดข้อง/ยังไม่เชื่อม, ข้อมูลเก่า, ส่งกลับแก้ไข, การเปลี่ยนเวอร์ชันเกณฑ์, เกณฑ์สาธิตกับคำขอจริง, การเปิดไฟล์โดยไม่มีสิทธิ์, นำเข้า CSV, รายงาน, log ไม่มีข้อมูลส่วนบุคคล, ปิดโหมดทดสอบ
