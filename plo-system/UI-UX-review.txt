รายงานตรวจ UI/UX — ระบบประเมิน PLOs (วิทยานิพนธ์ · สารนิพนธ์ · การค้นคว้าอิสระ)
=====================================================================
ไฟล์ในโฟลเดอร์นี้
  index.txt          = หน้าเว็บ (แก้แล้ว) → วางในไฟล์ HTML ชื่อ "index" ใน Apps Script
                       (Code.gs เรียก createHtmlOutputFromFile('index') ชื่อไฟล์ต้องตรงตัวพิมพ์)
  Code.txt           = โค้ดฝั่งเซิร์ฟเวอร์ (ไม่ได้แก้) → วางในไฟล์ Code.gs
  UI-UX-review.txt   = รายงานนี้

---------------------------------------------------------------------
ส่วนที่ 1 — สิ่งที่แก้ใน index.txt แล้ว
---------------------------------------------------------------------
00) [รอบ 3] ตัวประเมิน / วิเคราะห์ / วัดผล / รูบริกราย PLO
   - ซ่อนเมนู "เทียบ PLOs ข้ามหลักสูตร" ไว้ก่อน (โค้ดยังอยู่ เปิดกลับได้ภายหลัง)
   - ตาราง "โครงสร้างรูบริก: PLO 1 ข้อ แตกเป็นกี่เกณฑ์" (หน้า จัดการรูบริก และ วิเคราะห์ผล)
     บอกจำนวนเกณฑ์ คะแนนดิบเต็ม น้ำหนักในคะแนนรวม และรายชื่อเกณฑ์ของแต่ละ PLO
   - หน้าประเมินนักศึกษา: การ์ด "คะแนนแยกราย PLO ของกรรมการแต่ละคน"
     เช่น อ.บี ให้ PLO1 = 45/100 (9/20 คะแนน) พื้นแดงเมื่อต่ำกว่าเกณฑ์ผ่าน
   - หน้าวิเคราะห์ผล: สรุปราย PLO ของรุ่น, คะแนนราย PLO ของนักศึกษาแต่ละคน,
     และตารางแยกตามผู้ประเมิน (นักศึกษา × กรรมการ × PLO)

0) [รอบ 2] หน้าตาแบบระบบหลังบ้าน (Backoffice Dashboard)
   - เมนูด้านซ้าย (sidebar) มีไอคอน แบ่งกลุ่ม: เมนูหลัก / หลักสูตร / ผู้ดูแลระบบ
     เมนูที่เปิดอยู่มีพื้นสีฟ้าอ่อนและแถบสีน้ำเงินด้านซ้าย
   - เมนูของหลักสูตรเรียงใหม่: ภาพรวม → ตัวชี้วัด PLOs → จัดการรูบริก → วิเคราะห์ผล → ประเมินนักศึกษา → ส่งออก
   - แถบหัวด้านบนแสดงชื่อหน้าที่เปิดอยู่ + เส้นทาง (หน้าหลัก › ส่วนงาน › หลักสูตร)
   - ปุ่ม "รีเฟรชข้อมูล" มุมขวาบน: ดึงข้อมูลล่าสุดจากสเปรดชีตโดยอยู่หน้าเดิม
     (หลักสูตร แท็บ และนักศึกษาที่เปิดอยู่ไม่หาย) ถ้ามีงานที่ยังไม่บันทึกจะเตือนก่อน ไม่ทับข้อมูล
   - มือถือ/แท็บเล็ต (กว้าง < 1000px): เมนูซ้ายซ่อน กดปุ่ม ☰ เพื่อเปิด แตะเมนูหรือพื้นที่ว่างเพื่อปิด
   - การ์ด KPI มีแถบสีด้านซ้าย การ์ดมีเงาบาง ๆ แบบระบบหลังบ้านทั่วไป

1) เปิดระบบเป็นโทนสว่างเสมอ
   - เดิม: ถ้าเครื่องผู้ใช้ตั้งโหมดมืด (มือถือ/Mac ส่วนใหญ่ตอนกลางคืน) ระบบจะเปิดเป็นสีมืดเอง
   - ใหม่: เข้าระบบทุกครั้งเริ่มที่โทนสว่าง ไม่ว่าเครื่องตั้งไว้แบบไหน
     (ทดสอบแล้วด้วยเบราว์เซอร์ที่ตั้งโหมดมืด → ระบบยังเปิดเป็นสว่าง)

2) ปุ่มสลับโหมดมืด "☾ มืด" / "☀ สว่าง" มุมขวาบน
   - กดเปลี่ยนได้ทันที และใช้ได้ตั้งแต่หน้า "กำลังโหลดข้อมูล…" (เดิมปุ่มขึ้นหลังโหลดเสร็จเท่านั้น)
   - เลือกมืดแล้ว รีเฟรชหน้ายังคงมืด แต่ปิดแท็บแล้วเปิดใหม่จะกลับเป็นสว่าง
     ถ้าอยากให้จำโหมดมืดไว้ถาวร: ใน index.txt เปลี่ยน sessionStorage เป็น localStorage (มี 2 จุด)
   - ปุ่มมี aria-pressed ให้โปรแกรมอ่านหน้าจอรู้สถานะ

3) เตือนก่อนปิดหน้าเมื่อยังบันทึกไม่เสร็จ
   - ระบบบันทึกคะแนนอัตโนมัติหลังแตะ 0.6 วินาที ถ้าผู้ประเมินแตะคะแนนแล้วปิดแท็บทันที
     คะแนนข้อสุดท้ายอาจหาย ตอนนี้เบราว์เซอร์จะถามก่อนปิด
   - เตือนเช่นกันเมื่อแก้รูบริก / หัวข้อการประเมินแล้วยังไม่กด "บันทึก"

4) การเข้าถึง (Accessibility)
   - ข้อความแจ้งเตือน (toast) และสถานะ "กำลังบันทึก… / บันทึกแล้ว / บันทึกไม่สำเร็จ"
     ประกาศให้โปรแกรมอ่านหน้าจอ (aria-live)
   - ลิงก์ "หน้าหลัก", ชื่อส่วนงาน และ "แก้ PLO" ใช้แป้น Tab + Enter ได้ (เดิมใช้เมาส์ได้อย่างเดียว)

---------------------------------------------------------------------
ส่วนที่ 2 — จุดที่ดีอยู่แล้ว (ควรคงไว้)
---------------------------------------------------------------------
- ปุ่มให้คะแนนแบ่ง 5 ช่วง A–E พร้อมคำอธิบายของช่วงที่เลือก ชัดเจน กดง่ายบนมือถือ (สูง ≥ 44px)
- แถบล่างแบบติดจอ บอก "ให้แล้ว x/y เกณฑ์" + คะแนนรวม + ปุ่ม "ข้อที่ยังไม่ให้" / "คนถัดไป"
- คีย์ลัดบนคอมพิวเตอร์ (0–9, A–E) ช่วยให้กรรมการที่ประเมินหลายคนทำงานเร็ว
- อาจารย์ผู้ประเมินเห็นหน้าจอแบบย่อ และถ้าดูแลหลักสูตรเดียวจะเข้าหน้ารายชื่อนักศึกษาทันที
- ใช้ตัวแปรสีทั้งหมด (--bg, --ink, ...) ทำให้โหมดสว่าง/มืดเปลี่ยนได้ทั้งระบบ
- ความคมชัดของสีข้อความหลักผ่านมาตรฐาน WCAG AA ทั้งสองโหมด
  (ข้อความรอง #5b6773 บนพื้น #f4f6f8 = 5.3:1, ปุ่มหลัก = 6.4:1, ป้ายสถานะ ผ่าน/เตือน/ไม่ผ่าน ≈ 5:1)

ส่วนที่ 3 — ข้อเสนอแนะเพิ่มเติม (ยังไม่ได้แก้ เรียงตามความสำคัญ)
---------------------------------------------------------------------
[สำคัญ]
A. คะแนน 10 กดด้วยแป้นตัวเลขไม่ได้ (มีแค่ 0–9) ต้องกด "A" หรือแตะปุ่ม
   → เขียนใน "วิธีให้คะแนน" ให้ชัด หรือให้แป้น "0" สองครั้งติดกัน = 10
B. เมื่อบันทึกไม่สำเร็จ (เน็ตหลุด) ระบบแสดงแค่ข้อความเล็ก ๆ ไม่ลองใหม่เอง
   → ควรมีปุ่ม "ลองบันทึกอีกครั้ง" และลองซ้ำอัตโนมัติ 2–3 ครั้ง สำคัญมากตอนสอบในห้องที่ Wi-Fi ไม่ดี
C. ปุ่ม "ไม่ผ่าน" และ "ลบ" ควรมีขั้นยืนยัน (ตอนนี้ "ลบ" มีแล้ว แต่การโหวตผลสอบกดผิดง่ายบนมือถือ)
D. ตำแหน่งแถบติดจอใช้ค่าคงที่ (top:130px / 132px) ถ้าชื่อหลักสูตรยาวจนหัวเว็บสูงขึ้น
   กล่องด้านขวาจะซ้อนใต้หัวเว็บ → ควรคำนวณจากความสูงจริงของ .top

[ปานกลาง]
E. แท็บด้านบน (role="tab") ยังเลื่อนด้วยปุ่มลูกศรไม่ได้ และไม่มี tabpanel คู่กัน
F. ช่องค้นหารายชื่อ วาดหน้าใหม่ทุกตัวอักษร ถ้านักศึกษาหลายร้อยคนอาจหน่วงบนมือถือ
   → หน่วงเวลา 200ms ก่อนค้นหา (debounce)
G. หน้าแรกเมื่อโหลดไม่สำเร็จบอกให้ "รัน setup()" ซึ่งผู้ใช้ทั่วไปทำไม่ได้
   → แยกข้อความ: ผู้ใช้ทั่วไป = "ติดต่อผู้ดูแลระบบ", ผู้ดูแล = วิธีแก้
H. ข้อความขนาด 10.5–11px หลายจุด (คำอธิบายช่วงคะแนน, ป้ายเล็ก) อ่านยากบนมือถือ
   → ขั้นต่ำ 12px สำหรับภาษาไทยที่มีสระบน-ล่าง
I. กราฟแท่งซ้อน: ข้อความสีขาวบนสีส้ม (PLO ลำดับที่ 2) ความคมชัด 3.2:1 ต่ำกว่าเกณฑ์เล็กน้อย
   → ใช้ตัวอักษรสีเข้มเหมือน PLO ลำดับ 3–5

[เล็กน้อย / ภาพลักษณ์]
J. เพิ่มโลโก้หรือชื่อมหาวิทยาลัยบนหัวเว็บ ให้ผู้ใช้มั่นใจว่าเป็นระบบทางการ
K. หน้าจอ "กำลังโหลดข้อมูล…" ควรเป็นโครงร่าง (skeleton) แทนข้อความเฉย ๆ เพราะ Apps Script โหลดช้า 2–5 วินาที
L. ปุ่ม "พิมพ์/บันทึก PDF" ในหน้าผลของนักศึกษา จะช่วยงานเอกสารหลังสอบ

---------------------------------------------------------------------
ส่วนที่ 4 — วิธีอัปเดตใน Apps Script
---------------------------------------------------------------------
1. เปิดโปรเจกต์ Apps Script → ไฟล์ "index" (HTML) → ลบของเดิมทั้งหมด
2. คัดลอกทั้งหมดจาก index.txt → วาง → บันทึก
3. การทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้ → แก้ไข (ดินสอ) → เวอร์ชัน "ใหม่" → ทำให้ใช้งานได้
   (ถ้าไม่สร้างเวอร์ชันใหม่ ลิงก์เดิมจะยังแสดงหน้าเก่า)
