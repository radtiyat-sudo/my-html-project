รายงานตรวจสอบความปลอดภัย — ตัวช่วยจัดการเอกสาร (Code.gs + Index.html)
วันที่ตรวจ: 16 ต.ค. 2026
ขอบเขต: Code.gs, Index.html (โหมดแยกเอกสารรายคน + โหมดรวมไฟล์ PDF)

==================================================================
ภาพรวมสถาปัตยกรรม (Threat model)
==================================================================
- Code.gs มีแค่ doGet() ส่งหน้า HTML ไม่มีฟังก์ชันฝั่งเซิร์ฟเวอร์ที่เรียกผ่าน google.script.run
  -> ไม่มีช่องโหว่ฝั่งเซิร์ฟเวอร์ เช่น Injection เข้า Sheet/Drive หรือสิทธิ์ของผู้ Deploy รั่ว
- PDF ถูกอ่านและประมวลผลในเบราว์เซอร์ทั้งหมด ข้อมูลอ่อนไหว (ผลสอบ รหัสนักศึกษา) อยู่ในหน่วยความจำของหน้าเว็บ
- จุดเสี่ยงจริงจึงอยู่ที่ "โค้ดที่รันในหน้าเว็บ" คือ ไลบรารีจาก CDN และ PDF ที่ผู้ใช้เปิด (อาจถูกสร้างมาเพื่อโจมตี)
  ถ้าโค้ดแปลกปลอมรันในหน้าได้ ก็อ่านเอกสารทุกไฟล์ที่เปิดอยู่และส่งออกไปข้างนอกได้

==================================================================
ผลการตรวจ (เรียงตามความรุนแรง)
==================================================================

[1] สูง — PDF ที่สร้างมาโจมตีสามารถรัน JavaScript ในหน้าได้ (CVE-2024-4367)
    ประเภท: Code Injection / XSS ผ่านไฟล์
    ตำแหน่ง: pdfjsLib.getDocument({ data: ... })
    รายละเอียด: pdf.js เวอร์ชัน 3.11.174 มีช่องโหว่ CVE-2024-4367 (แก้ในเวอร์ชัน 4.2.67)
      ฟอนต์ใน PDF ที่ปลอมค่า FontMatrix ทำให้ pdf.js สร้างโค้ดด้วย new Function() แล้วรันโค้ดของผู้โจมตี
      เกิดตอนแสดงหน้า PDF (ปุ่ม "ดู" / แผนผังหน้า)
    ผลกระทบ: ถ้ามีคนส่ง PDF อันตรายมาให้เปิด ผู้โจมตีอ่านเอกสารทุกไฟล์ที่เปิดอยู่ ส่งออกนอกเครื่อง
      หรือแก้หน้าเว็บให้หลอกผู้ใช้ได้
    แก้ไข: ปิดการ eval ซึ่งเป็นวิธีแก้ที่ผู้พัฒนา pdf.js แนะนำเอง และปิด XFA ที่ไม่ได้ใช้
      pdfjsLib.getDocument({ data: bytes.slice(), isEvalSupported: false, enableXfa: false })
    ระยะยาว: อัปเกรดเป็น pdf.js 4.x ขึ้นไป (ต้องเปลี่ยนวิธีโหลดเป็น ES module)

[2] สูง — โหลดไลบรารีจาก CDN โดยไม่ตรวจความถูกต้อง (Supply-chain)
    ประเภท: Code Injection ผ่านบุคคลที่สาม
    ตำแหน่ง: <script src="https://cdnjs..."> / <script src="https://cdn.jsdelivr..."> และ workerSrc
    รายละเอียด: ไม่มี Subresource Integrity (SRI) ถ้าไฟล์บน CDN ถูกแก้ หรือถูกดักแก้ระหว่างทาง
      เบราว์เซอร์ก็จะรันโค้ดนั้นทันที โค้ดนั้นมีสิทธิ์เต็มเหนือเอกสารที่ผู้ใช้เปิด
      ไฟล์ worker ของ pdf.js ใส่ integrity ด้วย <script> ไม่ได้ จึงไม่มีการตรวจเลย
    แก้ไข:
      - ย้าย pdf.js มาใช้ jsDelivr แบบ npm (ไฟล์ตรงกับแพ็กเกจ npm ทุกไบต์) และใส่
        integrity="sha384-..." crossorigin="anonymous" ให้ทั้ง 3 ไลบรารี
      - ดาวน์โหลด worker ด้วย fetch(..., { integrity }) แล้วรันจาก blob: URL ของหน้าเอง
      - ทดสอบแล้ว: เมื่อไฟล์ worker ถูกแก้ ระบบหยุดและแจ้ง "โหลดเครื่องมือไม่สำเร็จ" ไม่รันโค้ดปลอม

[3] กลาง — PDF ที่แยก/รวมแล้วพา JavaScript ระดับหน้าติดไปด้วย
    ประเภท: Logic flaw / ส่งต่อเนื้อหาอันตราย
    ตำแหน่ง: out.copyPages(...) ทั้งโหมดแยกและโหมดรวม
    รายละเอียด: copyPages คัดลอกพจนานุกรมของหน้าทั้งหมด รวมถึง /AA (Additional Actions)
      ซึ่งใส่ JavaScript ที่รันเองเมื่อเปิดหรือปิดหน้าได้ ไฟล์ที่ระบบสร้างและส่งให้นักศึกษาจึงอาจพาสคริปต์ติดไป
      โดยที่ดูเหมือนมาจากหน่วยงาน
    แก้ไข: ตัด /AA ออกจากทุกหน้าก่อน addPage
      function stripPageActions(page) { page.node.delete(PDFLib.PDFName.of('AA')); return page; }
    ทดสอบแล้ว: ใส่ /AA ใน PDF ต้นฉบับ ไฟล์ผลลัพธ์ทั้งแบบแยกและแบบรวมไม่มี /AA
    ข้อจำกัด: ลิงก์ในหน้าที่ผูกกับ JavaScript (/Annots) ยังคงอยู่ หากต้องการตัดทั้งหมดต้อง rasterize หน้า

[4] กลาง — ชื่อไฟล์หลอกตาด้วยอักขระกลับทิศ / อักขระที่มองไม่เห็น
    ประเภท: Spoofing ผ่านชื่อไฟล์
    ตำแหน่ง: cleanName()
    รายละเอียด: อักขระอย่าง U+202E (RLO) ทำให้ชื่อ "abc‮fdp.exe" แสดงผลเป็น "abcexe.pdf"
      อักขระ zero-width ทำให้ชื่อไฟล์สองชื่อดูเหมือนกันแต่ไม่ซ้ำกันจริง จึงหลบการตรวจชื่อซ้ำได้
    แก้ไข: ลบ U+200B–U+200F, U+202A–U+202E, U+2060–U+2069, U+FEFF และ DEL ก่อนตั้งชื่อไฟล์
    หมายเหตุ: การกัน path traversal / Zip Slip ทำไว้ถูกต้องแล้ว (/ \ ถูกแทนด้วย -, ".." ถูกตัด)

[5] กลาง — CSV/Formula Injection ใน "รายการไฟล์.csv" ยังเลี่ยงได้
    ประเภท: Injection
    ตำแหน่ง: const cell = s => ...
    รายละเอียด: เดิมตรวจเฉพาะอักขระตัวแรก ถ้าขึ้นต้นด้วยช่องว่างแล้วตามด้วย "=" หรือขึ้นต้นด้วย "|"
      (DDE ใน Excel รุ่นเก่า) จะไม่ถูกกัน
    แก้ไข: /^[\s]*[=+\-@|]/ -> เติม ' นำหน้า
    ทดสอบแล้ว: ชื่อ =HYPERLINK(...) ถูกบันทึกเป็น '=HYPERLINK(...) เป็นข้อความธรรมดา

[6] ต่ำ — Information Disclosure ผ่าน Referer และ Google Fonts
    รายละเอียด: เวลาโหลด CDN และ Google Fonts เบราว์เซอร์ส่ง Referer และ IP ของผู้ใช้ไปให้ผู้ให้บริการ
      แต่ไม่ได้ส่งเนื้อหาเอกสาร
    แก้ไข: เพิ่ม <meta name="referrer" content="no-referrer"> และ fetch worker แบบ credentials:'omit'
    ทางเลือก: ถ้านโยบายไม่ต้องการให้ติดต่อ Google Fonts ให้ลบ <link> ฟอนต์ออก (หน้าจะใช้ฟอนต์ Tahoma/Leelawadee แทน)

[7] ต่ำ — ไม่กำหนด X-Frame-Options ให้ชัดเจน (Clickjacking)
    ตำแหน่ง: Code.gs doGet()
    รายละเอียด: ค่าเริ่มต้นของ Apps Script ปลอดภัยอยู่แล้ว แต่ไม่มีอะไรกันคนมาแก้เป็น ALLOWALL ภายหลัง
    แก้ไข: .setXFrameOptionsMode(HtmlService.XFrameOptionsMode.DEFAULT) พร้อมคอมเมนต์เตือน

==================================================================
จุดที่ตรวจแล้ว ไม่พบปัญหา
==================================================================
- XSS ผ่านชื่อไฟล์ / ข้อความใน PDF: ทุกจุดใช้ textContent และ createElement มีแค่ innerHTML เดียว
  (ROW_HTML) ซึ่งเป็นข้อความคงที่ ไม่มีข้อมูลจากผู้ใช้
- ReDoS: regex ทุกตัวมีขอบเขตจำกัด ไม่มี nested quantifier
- ข้อมูลค้าง: ไม่ใช้ localStorage/cookie, revoke blob URL ตอน pagehide และตอนสร้างใหม่, pdf.destroy() เมื่อล้างไฟล์
- Race condition: ทุก action ตรวจ state.busy และล็อก fieldset ระหว่างประมวลผล
- จำกัดขนาด 30 MB / 300 หน้า (แยก) และ 30 MB / 600 หน้า / 100 ไฟล์ (รวม) กันเบราว์เซอร์ค้าง
- PDF ที่เข้ารหัส: ปฏิเสธพร้อมข้อความชัดเจน ไม่ใช้ ignoreEncryption

==================================================================
ข้อแนะนำการ Deploy
==================================================================
- Execute as: Me (USER_DEPLOYING) ได้ เพราะไม่มีฟังก์ชันเซิร์ฟเวอร์
- Who has access: ใช้ "ภายในโดเมน" (DOMAIN) อย่าเปิด "Anyone" ถ้าไม่จำเป็น
- ถ้าภายหลังเพิ่ม google.script.run ต้องตรวจสิทธิ์ (Session.getActiveUser) และ validate input ฝั่งเซิร์ฟเวอร์ทุกครั้ง
- เมื่ออัปเกรดไลบรารี ต้องคำนวณค่า SRI ใหม่:
  openssl dgst -sha384 -binary FILE | openssl base64 -A
